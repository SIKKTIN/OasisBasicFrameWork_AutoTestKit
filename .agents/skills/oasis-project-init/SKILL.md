# Oasis 项目上下文初始化

每个新对话开始开发前，先理解项目，再开展本次工作。初始化的结果是当前对话对项目目标、架构、开发规则、实现现状与待办的认识；此流程只读，不创建业务初始结构、不部署框架、不修改配置或文档，也不自动执行生成器、测试或 PIE。

## 确定阅读对象

区分工具仓库与本次目标项目：本 skill 真实源目录向上三级是 OasisBasicFrameWork_AutoTestKit 工具根目录。通过用户级链接加载时先解析真实目标；单独复制而无法定位时，使用用户提供的位置，仍不明确再询问。

目标优先使用用户明确指定的项目。未指定时，核对当前工作目录及上级目录中的项目标识、README 或 .ugcproj，能够唯一确定就继续；存在多个候选或目录含义不明时，只询问目标目录。不得用工具 setting.json 中的旧 projectRoot、模板来源项目或 MCP 当前工程替代本次目标。若本次工作就在工具仓库，则初始化工具仓库的上下文，不强行要求业务工程。

读取适用的 AGENTS.md 和项目约定。初始化不依赖完整环境配置：Lua、CSV 和 MCP 未提供时仍可阅读本地文档与源码，无需先触发环境检测或部署预检。

## 先读文档，形成项目认识

先发现文档入口，再沿导航阅读，避免递归加载整个 Docs 或源码树。

1. 阅读目标项目的 README、文档索引和开发约定，明确项目用途、设计目标、目录职责、开发与验证方式。文档路径按实际目录发现，不假设每个项目都有固定名称的设计或进度文件。
2. 阅读工具仓库 README.md、Docs/framework/README.md 与 Docs/framework/Project_Architecture.md，理解通用框架与工具职责；结合 Docs/framework/Package_Structure.md 和 Package_Meta.md 掌握包公共入口、依赖及声明规则。同一对话已读且未发生相关变化的资料无需重复加载。
3. 查阅目标项目现有的设计、进度、待办、已知问题和交接记录，区分已实现、计划中、已验证与待验证。按内容和实现证据判断当前状态，日期或文档排序只用于定位，不自动代表结论仍有效。未找到进度记录时如实说明，不创建文件，也不声称已经读取其他对话。
4. 按本次任务补读专题资料：数据与存档看 Docs/framework/DataCore_Guide.md；调试和验收看 Development_Test_Debug_Guide.md；生成器看 GenKit/README.md；编辑器及 API 先看 Docs/OasisGuide.md，再定位具体条目。目标项目自己的约定与通用规范有差异时，指出差异及其影响，不直接套用模板改写。

先在心中建立 Core、Package、Const、Config、Event、Setting 的职责关系，识别手写输入与生成产物，理解 Registry、Meta、数据声明和事件契约。通用文档中的项目名和业务示例不代表目标已采用这些内容；目标的业务行为以其自身文档和实现为依据。

## 再核对实际现状

结合文档检查目标的目录结构、相关入口、已接入模块和配置声明。存在 Git 仓库时只读查看当前分支及工作区差异，了解已有修改；不重置、清理或覆盖任何内容。按本次任务定位关键实现，不在初始化时审查全部业务或读取所有资产。

UGC 工程可从 .ugcproj 和已绑定入口的可读信息确认启动关系，并抽查相关 Registry、Package_Meta、Setting 与生成器输入。工具仓库则核对实际工具入口、模板与文档位置。模板清单只能证明可部署内容，不能证明目标已经部署；生成文件存在不能证明内容最新。

文档与代码不一致时同时记录文档意图和当前实现，不能把规划当作现成功能。历史测试报告说明过去的验证范围；源码阅读、静态检查和本次实际运行结果分开表述。本流程不为获取“通过”结果而自动运行测试或连接编辑器；本次任务确实需要运行检查时，再在该任务范围内处理。

若用户已给出具体任务，围绕相关模块建立上下文，保留必要的项目全貌；若仅要求初始化，阅读到足以说明项目定位、核心规则和当前状态即可，不擅自挑选待办执行。资料缺失时继续检查可用实现，只对影响本次工作的关键信息询问。

## 向用户说明当前理解

输出简明的项目认识，优先说明：

- **本次对象与目标**：正在处理的项目及目录，项目用途，以及本次任务（若已指定）。
- **架构与工作规则**：与后续工作直接相关的模块关系、目录约定、手写与生成边界、验证方式。
- **当前状态**：有证据支持的已完成内容、现有修改、待办及已知问题，避免把所有模块逐项罗列。
- **不确定项**：文档与实现的差异、缺少的信息和未验证范围；没有关键不确定项时无需单列。

附少量实际读过的关键文档或源码链接，方便用户核对。没有进度文档就明确缺失，不凭代码数量推断完成率；未实际运行不宣称能正常启动。

只要求初始化时，完成说明后结束，不额外要求用户确认阅读结果。有明确后续任务时，简要说明理解后继续已授权的工作，仅在必要信息缺失或存在实质冲突时询问。上下文用于本次对话，不声称会自动永久记住或同步到其他对话；用户另行要求保存交接记录时再写入。
