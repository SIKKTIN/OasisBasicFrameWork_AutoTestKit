# Oasis 项目文档维护

为已授权的开发或文档任务维护必要记录，与实际实现同步。完整规则统一读取 [Oasis 项目文档规范](../../../Docs/framework/Project_Documentation_Guide.md)，本 Skill 不另写一份分类或模板规范。

## 定位项目与规则

- 本 Skill 真实源目录向上三级为 TestHelper 工具仓库；通过用户级目录联接加载时先解析真实目标。规则文件无法定位时使用已提供的仓库位置，仍缺失再询问，不转而依赖个人目录中的其他 Skill。
- 目标优先采用用户本次明确的工程；否则从工作目录、项目约定和现有实现确认。工具仓库自身开发也适用。不能因当前编辑器或旧 setting.json 指向某项目，就把本次记录写到那里。
- 根据项目约定、README 和现有资料确认是否采用 Oasis。上下文尚不明确时先检查可用信息，不向其他框架项目套用此规范。
- 阅读适用的 AGENTS.md、实际文档导航和相关事项。新项目默认导航为 Docs/目录.md、进度为 Docs/dev/目录.md；已有 docs、Docs/module、Docs/plan 或等价目录保留并明确映射。TestHelper 自身沿用根 README、Docs/framework/README.md 与 Docs/dev/目录.md。

## 日常开发时主动维护

用户提出 Oasis 项目的功能开发、Bug 修复、优化或重构时，将文档维护作为该事项的一部分，无需另等“更新文档”的指令，也不为写每份记录重复要求确认。已有任务计划或其他 Oasis Skill 正在维护同一事项时直接接续，避免另建重复计划。

1. **实施前**：沿导航阅读相关设计、具体内容与已有开发记录，核对关键实现。接续原事项，或在目标实际开发目录新增本事项计划；写清目标、范围、涉及文件、步骤和验证方式，再修改实现。小改动简写，概念讨论不提前变成开发事项。
2. **实施中**：同步实际改动、范围调整、关键决定、失败与接续点。业务规则不明确时保留待确认，不把自己的推测写成既定设计。
3. **完成时**：在同一事项中补实际结果、验证证据和未完成内容，更新进度索引。行为、配置或具体内容变化时同步其负责文档；没有机制变化不重写设计。技术接口变化时按需维护包 README，并链接到项目资料。
4. **检查与交付**：核对导航和相对链接、文档与实际配置/资源入口、状态与证据一致性。报告本次维护的主要文档及仍未验证的范围。实现完成但必需验收未完成时标待验收；用户要求不测试则如实记录。

## 新建、整理或补齐文档

明确要求建立导航、写设计、整理目录或补开发记录时，在指定范围内执行。依据实际资料形成正文和必要目录，优先链接已有文档；新增或更新入口以便找到资料，不预建空分类，不批量搬迁已有文档。只补能核实的历史记录，缺少资料时标明缺失，不补造测试、进度或项目设计。

项目业务文档写在目标工程，框架开发文档写在 TestHelper。长期规则、具体实例、实施过程分别按统一规范归属，其他地方引用同一份正文；实际代码、配置、资产与验证产物继续遵循项目约定。

## 写入与协作边界

- 仅问答、评估、只读审查、仅计划或项目上下文初始化时，只读取和汇报；除非用户明确要求保存计划或撰写文档，不为留痕新建记录。
- 框架初装和可选包增装继续遵循各部署 Skill 的预检确认流程：确认前只规划文档变更，确认后才写事项计划和导航。此 Skill 的主动选用不能替代部署确认，也不创建第二份部署记录。
- 普通开发写事项计划、实施记录及必要导航属于任务范围；重组整个文档树、删除历史、改变未确定的玩法或部署范围不能由此推定已获授权。
- 本 Skill 不独立触发生成器、MCP 写入、PIE、上传或测试；这些操作由实际开发任务及其授权决定。静态检查、隔离测试、编辑器、PIE 与发布环境证据分别记录，历史通过不等于本次验收。

主动选用是执行请求时的任务匹配，不是文件变化监听或后台同步；实际触发和维护效果需在真实开发中核对。
