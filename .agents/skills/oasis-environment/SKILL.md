# Oasis 环境配置检测

只检查 `setting.json` 中的三项环境配置，按必需和可选分类汇报，缺失必需项时请用户补全。

## 定位配置

源文件位于工具仓库的 `.agents/skills/oasis-environment/`，向上三级定位根目录并读取 `setting.json`。通过用户级链接加载时先解析真实目标；单独复制安装且无法确定工具位置时，再向用户询问位置。

工具根目录只用于内部定位配置，不作为检查项或报告项，不检查 GenKit、PackageKit、ExternalConfig 是否完整。

配置文件缺失或 JSON 无法解析时，报告具体问题并收集必需配置；不要用空白模板覆盖无法解析的现有配置。

## 检查项

| 类别 | 字段 | 检查 |
| --- | --- | --- |
| 必需 | `projectRoot` | 非空的项目根目录绝对路径，目录存在且可访问。 |
| 必需 | `luaPath` | 非空的 Lua 解释器绝对文件路径，文件存在，执行 `-v` 验证为 Lua 5.4。 |
| 可选 | `dataTableCsvRoot` | 已配置时，仅检查是否为有效、可访问的目录绝对路径；缺失或空值标为“未配置（可选）”。 |

目标项目以配置或用户明确指定的项目为依据，不根据当前工作目录自动切换。用户指定项目与配置不同且需要处理时，简短说明差异。

使用 PowerShell 检查路径时使用 `-LiteralPath`；解释器路径作为独立参数调用，不拼接执行字符串。版本检测设置约 5 秒的有限等待；启动失败、超时或执行受限时标为“未验证”并简述原因，停止本次检测启动的进程，不无限等待或反复重试。文件存在不代表解释器已验证。

只检查以上三项。不读取 CSV 内容、表头、表声明或生成输出，不检查其他相对路径，不运行生成器、Package 诊断或业务测试。

## 报告与补全

先给一句结论，例如“必需配置可用”或“必需配置尚未完整验证”，再按必需配置、可选配置分组列出三项的实际路径和状态。Lua 验证成功时附版本号；异常只补充定位问题所需的一句话。

可选配置缺失或无效不影响必需配置的通过结论，按实际状态单独报告。不默认解释配置用途、CSV 工作原理或工具目录结构，不附命令执行记录和与结果无关的操作声明。用户追问用途时再解释。

- 必需项缺失、路径无效或 Lua 版本不符：先完成其余独立检查，再一次性请用户补充项目目录和/或 Lua 5.4 解释器路径。已知有效项无需重新提供。
- 解释器仅因执行限制未验证：说明当前限制，保留原值，不直接要求更换路径。
- 可选项未配置：仅报告，不要求用户补填。用户主动需要配置时再收集路径。
- 默认检查不修改配置。用户要求初始化、补全或切换配置且已提供明确值时，直接更新相关字段并复查，保留其他字段和已有修改。

本 skill 负责环境配置检测；框架和工具介绍由 oasis-introduce 负责。
