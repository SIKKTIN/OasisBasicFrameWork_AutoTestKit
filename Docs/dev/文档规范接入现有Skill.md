## 目标与范围

将 [Oasis 项目文档规范](../framework/Project_Documentation_Guide.md) 接入现有的项目上下文初始化、基础框架部署和可选包增装 Skill。规则集中维护在仓库规范中，不新增 Skill，不依赖外部文档 Skill。

## 涉及文件与步骤

1. `.agents/skills/oasis-project-init/SKILL.md`：明确导航、进度和相关资料的阅读路径，保持初始化只读。
2. `.agents/skills/oasis-project-deploy/SKILL.md`：文档现状和写入范围进入预检；确认后建立必要导航、事项计划，收尾维护接入与验收结果。
3. `.agents/skills/oasis-package-deploy/SKILL.md`：复用既有文档目录和记录，补齐本次增装配置、接口、生成与验证情况。
4. 更新规范与导航的“尚未接入”描述，保留原文档编写记录并登记本事项。
5. 检查链接、Skill 元数据、授权边界、只读与写入步骤一致性；以 TempleTest 的实际文件状态做只读流程检查。真正部署和 PIE 仍须满足对应 Skill 的当前预检确认要求，不能用此次 Skill 修改授权覆盖未知的工程改动。

## 验证方式

尝试自带 Skill 校验器；若缺少依赖，如实记录并进行有限静态检查。核对所有新增引用和原有界面元数据，审阅空项目、已有导航、仅初始化、仅计划、确认后部署和失败接续等情景。只读检查不生成目标文档、不改变实际工程或运行状态。

## 实施结果

已在三个 Skill 中加入对仓库统一规范的相对链接与各自执行步骤。初始化明确实际导航、进度与缺失资料的阅读和汇报；两个部署 Skill 将文档变更列入预检，确认后备份并形成事项计划，收尾更新接入说明、证据和进度。失败接续、仅检查、仅计划及已安装无变更均有明确写入边界。

流程情景审阅（文档决策检查，不是目标部署运行测试）：

| 情景 | 检查结论 |
| --- | --- |
| 仅初始化或缺少文档 | 定位实际资料、报告缺失，不创建文档、不运行编辑器 |
| 已有不同目录与导航 | 复用项目声明的路径，不搬迁或新建第二套文档根 |
| 部署仅计划或尚未确认 | 只列文档现状及拟变更，初始化也不能提前写部署计划 |
| 已确认部署 | 文档纳入备份，先形成事项计划，再接入并记录实际结果 |
| 部分失败或待验收 | 记录已执行范围、未完成步骤和接续点，不标全部完成 |
| 已安装且无需变更 | 检查后汇报，不为留痕改写目标文档 |
